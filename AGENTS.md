# AGENTS.md — agent-net-doctor

## Что за проект

Диагностический скрипт на bash для Claude Code и Codex. Он находит участок, на котором
рвётся связь агента с API: мост WSL↔Windows, прокси, DNS/IPv6, перехват TLS, туннель.
Поддержка в v0.1.0: WSL2 + Ubuntu полностью, Ubuntu без WSL — общие проверки.
Цель и срез — в `PLAN.md`.

Отвечай по-русски. Тексты README и вывода скрипта — тоже по-русски.

## Главные правила

- **Скрипт только читает и меряет.** Он не меняет настройки системы, WSL, VPN
  или агентов. Совет «что поменять» печатается, выполняет его человек.
- **Ничего не выдумывай.** Хосты агентов берутся с их бинарей (`strings`) и хранятся
  в `hosts/` с датой и версией. Хост, которого нет в бинаре, в проверку не попадает:
  ложный ✗ в диагностике дороже отсутствующей проверки.
- **Адреса скрыты по умолчанию.** Публичные IP, адреса прокси, логины и пароли в адресе
  прокси в вывод не попадают. Полные адреса — только с флагом `--show-ip`.
- **Определение WSL** — по `WSL_DISTRO_NAME`, `/proc/sys/fs/binfmt_misc/WSLInterop`,
  `wslinfo`. Не по `uname -r`: docker внутри WSL наследует то же ядро.
- **Зависимости:** bash, curl, iproute2. python3 по желанию: без него контрольный
  замер пропускается, скрипт не падает.
- Код пишется заново под этот проект. Из других проектов и учебных комплектов
  ничего не копируется.

## Ключи

Проекту ключи не нужны совсем. Файл `.env` не читай, ключи в чат не выводи.
Запрет на чтение стоит в `.claude/settings.json` — не меняй его.

## Проверки

До сборки проверок нет. На сборке появятся:
- `docker run --rm -v "$PWD:/mnt" koalaman/shellcheck:stable net-doctor.sh` — без ошибок;
- `bash tests/run.sh` — сценарии поломок, у каждого свой ожидаемый вердикт.

Задача считается сделанной, когда проверки зелёные. Сохранение — после каждой задачи.

## Что нельзя трогать

- `.claude/settings.json` — запрет на `.env`
- `LICENSE` — текст лицензии не правится
- `version` и теги релизов — только по просьбе автора

## Память и чекпоинты (только у автора, в git не идут)

Папки `memory/` и `sessions/` под `.gitignore`. Если их нет, этот раздел пропусти.

- В начале работы прочитай `memory/dolgosrochnaya-pamyat.md`, затем последний файл
  из `sessions/`.
- Решение, которое должно пережить окно, записывай в `memory/dolgosrochnaya-pamyat.md`
  одной строкой: дата, что решили, почему. Сначала спроси «записать?».
- По фразе «сделай чекпоинт» создай или дополни `sessions/ГГГГ-ММ-ДД-chekpoint.md`.
  Разделы: «Что сделано» (пути, числа), «Решения» (почему так), «Не завершено»
  (следующий шаг).
- Встроенная память Claude Code держит только указатель на эти файлы. Факты туда
  не дублируются: две памяти расходятся.
- Рассуждения, ключи, имена людей и сетевые адреса в память не пиши.

# PLAN — agent-net-doctor v0.1.0

## Одна фраза

Тот, у кого Claude Code или Codex в WSL2 или Ubuntu висит на «Waiting for API response»,
за минуту узнаёт, на каком участке рвётся связь и что поменять. Не нужно гадать
«это VPN» и переустанавливать.

## Вертикальный срез

Один сценарий от начала до конца:

1. Человек скачивает `net-doctor.sh` по README и запускает `bash net-doctor.sh`.
2. Скрипт определяет среду: WSL2 или Ubuntu без WSL, какие агенты стоят.
3. Читает режим сети WSL и прокси-переменные. Меряет:
   - прямой доступ и доступ через прокси;
   - серию подключений к прокси-порту против контрольного порта внутри WSL;
   - эндпоинты установленных агентов;
   - DNS/IPv6 и TLS.
4. В конце печатает одну строку «где рвётся» и одну «что поменять».
   Код выхода: 0 здоров, 1 найдена поломка, 2 среда не поддерживается.
5. Сетевые адреса в выводе скрыты, так что вывод можно показать на экране
   или вставить в issue.

Как проверить, что сработало: вердикт совпал с тем, что человек потом поменял,
и агент перестал виснуть. На здоровой сети вердикт «сеть здорова».

## Чего нет в первой версии

- macOS: вежливый отказ и код 2. Поддержка в v0.2, если найдётся тестер с Mac
- Windows PowerShell
- проверка MTU
- самостоятельная починка: скрипт только читает и меряет
- настройка VPN-клиентов
- серверная сторона Anthropic и OpenAI: если сеть здорова, скрипт так и говорит

## Задачи

По одной на разговор: что сделать и как проверить. Задача готова, когда её проверка
зелёная и сделан коммит. С задачи 2 у каждой задачи общая проверка: shellcheck без
ошибок и `bash tests/run.sh` зелёный. Сценарии поломок в тестах растут вместе
с проверками: каждая новая проверка приносит свой сценарий.

Сценарии в тестах работают без сети и без WSL. Внешние команды (`curl`, `ip`,
`wslinfo`, `getent`, `python3`) подменяются заглушками через `PATH`, а системные файлы
(`/proc/...`, `/etc/resolv.conf`, `.wslconfig`) скрипт читает от корня, который тест
может переопределить. Так один сценарий = папка с заглушками + ожидаемый вердикт
и код выхода.

### 1. `hosts/` из бинарей

Сделать: снять `strings` с бинарей Claude Code и Codex, выбрать хосты API и служб,
к которым агент ходит при работе. По файлу на агента: `hosts/claude-code.txt`,
`hosts/codex.txt`. В шапке — версия агента, дата, команда, которой сняты хосты.
Для каждого хоста — зачем он нужен агенту (API, вход, обновления, телеметрия).

Проверить: каждый хост из файла находится `grep`-ом в бинаре указанной версии.
Хоста, которого нет в бинаре, в файле нет. Хосты документации, примеров и сторонних
библиотек не взяты.

### 2. Каркас скрипта и тестов

Сделать: `net-doctor.sh` с разбором ключей (`--show-ip`, `--help`, `--version`),
функцией скрытия адресов, печатью шагов ✓/✗/–, кодами выхода 0/1/2 и отказом
на macOS. `tests/run.sh` — прогон сценариев из `tests/cases/` с заглушками
по схеме выше.

Проверить: сценарии «macOS → код 2», «адрес прокси с логином и паролем скрыт»,
«с `--show-ip` адрес виден». Бит исполнения — через `git update-index --chmod=+x`.

### 3. Среда и настройки WSL

Сделать: определить WSL2 (`WSL_DISTRO_NAME`, `WSLInterop`, `wslinfo`), docker внутри
WSL, Ubuntu без WSL. Найти установленные агенты и их версии. Прочитать режим сети
(`wslinfo --networking-mode`, `.wslconfig`) и прокси-переменные, отметить прокси,
импортированный из Windows.

Проверить: сценарии «WSL2 nat», «WSL2 mirrored», «docker в WSL — не WSL»,
«Ubuntu без WSL», «агентов нет». На машине автора — режим `nat`, оба агента найдены.

### 4. Мост до прокси

Сделать: серия из 10 подключений к прокси-порту и столько же к контрольному порту
внутри WSL (контрольный сервер — python3; без него замер пропускается с пометкой).
Посчитать удачные и время каждого.

Проверить: сценарий «4/10, удачные по ~1 с против 10/10 за миллисекунды» даёт
вердикт «рвётся мост WSL↔Windows до прокси». Сценарий «без python3» не падает.

### 5. Эндпоинты, DNS/IPv6, TLS

Сделать: прямой доступ и доступ через прокси к хостам из `hosts/` установленных
агентов. DNS: имя разрешается. IPv6: есть адрес, но нет маршрута — отметить.
TLS: издатель сертификата не из ожидаемых — отметить перехват.

Проверить: сценарии «прямой доступ в чёрную дыру, через прокси работает»,
«DNS не отвечает», «IPv6 без маршрута», «чужой издатель сертификата».

### 6. Вердикт и советы

Сделать: правила «где рвётся» по результатам шагов 3–5 и одна строка «что поменять»
на каждый вердикт. Совет только печатается. Вердикт «сеть здорова», если всё ✓.

Проверить: у каждого сценария из `tests/cases/` ровно один ожидаемый вердикт
и он совпадает. Сценарий «mirrored + VPN + потери на мосту» советует
`networkingMode=NAT` и `autoProxy=false`.
